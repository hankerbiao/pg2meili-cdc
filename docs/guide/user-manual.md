# 用户引导手册

本手册面向首次接触 UniData 的使用者，提供从获取 Token 到写入数据、搜索与排障的完整上手路径。

## 适用人群

- 业务应用开发者：需要接入统一数据管理与搜索能力
- 数据平台运维或管理员：需要开通应用、审核 Token、查看数据写入情况
- 测试或运营人员：需要查询或验证数据可检索性

## 上手路径

### 1. 明确访问目标

- 如果你要写入或管理业务数据，使用 `管理接口 (Management API)`。
- 如果你只需要检索数据，使用 `搜索接口 (Search API)`。

建议先确认自己属于哪种角色，再按下列步骤执行。

### 2. 申请并获取 Token

- **开发自助**：优先参考 `Token 认证` 说明，获取可用 JWT。
- **内部申请**：如使用自助申请页面，提交申请后等待管理员审核并下发 Token。

完成后，你将获得一个 `Bearer Token`，用于调用所有需要鉴权的接口。

#### 申请 JWT 的操作流程（自助申请页面）

1. 打开 `http://后端服务:8080/app/register` 页面（确保可访问后端 API，默认 `/api/v1/...`）。
1. 填写申请信息：
   - `app_name`：应用唯一标识（建议与服务名一致）
   - `失效日期`：Token 过期时间
   - `接收人 ITCode`：Token 下发目标用户
1. 提交申请，状态为 `pending`。
1. 管理员审核通过后状态变为 `approved`，Token 将通过内部光圈通知发送给接收人。

### 3. 选择索引或集合

- **写入场景**：确定业务集合名（`collection`），例如 `testcases`、`requirements`。
- **搜索场景**：确认搜索索引名（通常与集合一致，或由管理员配置的索引名）。

### 4. 写入数据（管理接口）

最常用的写入接口是：

```http
POST /api/v1/data/{collection}
Authorization: Bearer <jwt>
Content-Type: application/json

{
  "id": "demo_001",
  "title": "示例文档",
  "content": "这是一个写入与搜索的示例"
}
```

### 5. 触发搜索（搜索接口）

```http
POST /search
Authorization: Bearer <jwt>
Content-Type: application/json

{
  "q": "示例",
  "limit": 10
}
```

如需更复杂的过滤与排序，请查看搜索接口文档中的参数说明。

## 常见操作流程

### 写入与检索验证

- 先通过管理接口写入一条数据。
- 等待同步完成后，使用搜索接口查询关键词。
- 若搜索不到，优先检查 Token、索引名、数据是否成功写入。

### 多应用隔离

- 每个应用使用独立的 `app_name`。
- 不同 `app_name` 之间的数据与索引隔离。
- 若查询不到数据，检查是否使用了正确的 Token。

## 排障清单

### 1. 返回 401 / 403

- Token 是否过期。
- Token 是否属于当前应用。
- 请求头是否包含 `Authorization: Bearer <jwt>`。

### 2. 写入成功但搜索不到

- 同步是否完成（CDC 或同步服务是否运行）。
- 索引名称是否匹配。
- 搜索关键词是否存在于写入字段中。

### 3. 请求超时或 5xx

- 服务是否存活，检查 `/health`。
- 网络环境是否可达（内网或测试环境）。
